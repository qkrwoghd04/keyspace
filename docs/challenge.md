# 30초 Challenge

닉네임 기반 익명 경쟁. 한국어와 영어의 고정 지문별 순위, 참가자별 최고 기록 한 개와 내 이력 제공. Playground의 14개 테마와 디지몬 최종 진화 유지. 운영 배포는 별도 단계.

## 화면과 판정

- 준비: 최초 닉네임, 언어와 시작. 3초 준비 후 30초 경기, 취소 가능.
- 경기: 지문, 확정 입력, 남은 시간, 글자/초와 정확도. 테마와 모드 변경 잠금, 사운드 조절 유지. 기록 목록 숨김.
- 결과: 글자/초, 정확도, 서버 저장 상태와 다시 시작. 실패 시 같은 경기 ID로 저장 재시도.
- 아래 순위 / 내 기록 탭, 20개씩 조회. 화면 진입과 저장 후 갱신, 자동 폴링 없음.
- Ghost, 코드 지문, 시간 선택, 콤보, 효과 설정, 보상 입자, 완주 연출과 홍보 문구 제거.

공유 판정 규칙 `correct-prefix-cps-v2`:

| 항목 | 정의 |
| --- | --- |
| 글자 | NFC 정규화 후 완성 grapheme 하나. 한글 음절, 공백과 문장부호 각각 1글자 |
| 정답 수 | 처음부터 오타 없이 일치하는 현재 위치. 오타 뒤 글자는 오타 수정 전 진행 불가 |
| 현재 속도 | 현재 정답 수 / 경과 초 |
| 최종 속도 | 현재 정답 수 / 30. 종료 직전 삭제한 글자는 제외 |
| 정확도 | 통과한 고유 정답 위치 / (고유 정답 위치 + 누적 오타) × 100 |
| 삭제와 재입력 | 삭제 자체는 오타 아님. 같은 위치 재입력으로 고유 정답 수 증가 없음. 수정해도 과거 오타 유지 |
| IME | 조합 중간값 제외, 확정 입력 한 번만 반영. 종료 시 미확정 조합 제외 |
| 종료 경계 | 단조 시계 기준 30,000ms 이상 입력 제외. 타이머 콜백 횟수와 무관 |
| 취소 | 취소, 탭 숨김과 페이지 이탈은 결과 미제출, 티켓 취소 요청 |
| 입력 제한 | 붙여넣기, 드롭, 실행 취소/다시 실행 차단. Playground의 정상 편집은 유지 |

## 데이터와 API

동일 서비스에서 정적 화면과 API 제공. Node.js 24, Fastify, better-sqlite3의 SQLite 사용. 시작 시 SQLite >=3.51.3 검사, WAL + synchronous FULL + foreign keys 활성화. 실제 검증 버전 3.53.4. [SQLite WAL 안내](https://sqlite.org/wal.html)

| 요청 | 역할 |
| --- | --- |
| GET /api/player | 현재 쿠키의 참가자 또는 null |
| POST /api/player | 최초 닉네임 등록, 기존 참가자는 그대로 반환 |
| POST /api/runs | 언어별 서버 티켓 발급, 기존 미완료 티켓 취소 |
| POST /api/runs/:id/finish | 확정 편집 이력 재계산, 한 번만 저장 |
| DELETE /api/runs/:id | 본인 미완료 경기 취소 |
| GET /api/leaderboard?choice=korean&offset=0 | 공개 최고 순위, 20개 + hasMore |
| GET /api/records?choice=korean&offset=0 | 현재 참가자의 이력, 20개 + hasMore |
| DELETE /api/records | 현재 참가자의 모든 언어 이력과 티켓 삭제 |
| GET /api/health | DB 연결 상태 확인 |

`choice`는 korean / english. 경기 ID는 서버 생성 UUID. 티켓에 지문 ID, 버전, 판정 규칙, 서버 발급 시각 및 제출 만료 시각 연결. 3초 준비와 30초 이전 제출 거부, 종료 예정 시각부터 10분 내 제출 가능. 이미 저장된 경기의 재시도는 만료 후에도 같은 결과 반환. 삭제한 경기의 재시도는 복원 불가.

편집 이력은 `{ at, start, deleteCount, insert }` 배열. 글자 단위 변경 구간만 전송하며 매 키 통신 없음. at은 경기 시작 기준 ms, 서버에서 순서, 범위, 30초 경계와 편집 범위 검증 후 공유 판정기로 재계산. 클라이언트 속도나 정확도 필드 수신 거부. 최대 4,096회 편집, 한 편집의 삽입 문자열 1,024 UTF-16 코드 단위, 전체 요청 256KiB 제한.

DB에는 참가자 ID, 토큰 해시, 닉네임과 생성 시각, 경기 조건/시각/상태, 점수만 보관. 편집 원문은 요청 메모리에서 검증 후 폐기, DB 및 요청 로그에 저장하지 않음. Playground 문장과 키 입력은 서버 전송 없음.

- 256비트 난수 쿠키, 서버에는 SHA-256 해시만 저장.
- 운영 쿠키: HttpOnly, Secure, SameSite=Lax, Path=/api, 1년. 닉네임은 소유권 기준 아님.
- 변경 요청은 정확한 PUBLIC_ORIGIN 확인. 모든 개인 조회는 쿠키 확인. 쿠키/본문/쿼리 문자열 로그 제외.
- 참가자별 분당 시작 6회, 제출 12회, 취소 12회, 이력 삭제 3회.
- 익명 생성은 IP당 시간당 120회, 일반 조회는 IP당 분당 6,000회. 같은 네트워크의 100명 첫 참여 지원.
- 프록시 신뢰는 기본 없음. 실제 프록시 IP/CIDR만 지정, 임의 X-Forwarded-For를 신뢰하는 전체 허용 금지.
- 저장과 티켓 갱신은 짧은 단일 트랜잭션. 기본키와 소유권 조건으로 중복 및 타인 기록 변경 방지.
- 언어/지문/규칙/참가자와 이력 조회 인덱스, 2초 내부 순위 캐시. 새 저장과 삭제 시 무효화.

## 순위와 개인 기록

동일 언어, 지문 ID/버전, 판정 규칙의 기록만 순위에 포함. 참가자별 정답 수 → 정확도 → 먼저 서버에 저장된 시각 → 경기 ID 순서로 최고 기록 하나 선정. 모든 경기가 30초이므로 정답 수 순서는 속도 순서와 동일. 0점은 순위에서 제외하되 개인 이력에는 유지. 기간 초기화 없음.

기존 `keyspace:challenge:v1` 자료는 읽거나 삭제하거나 서버로 이전하지 않음. 내 기록 삭제는 서버의 현재 참가자 기록만 삭제. 원본 DB 삭제 후에도 운영 백업에는 보존 기간 동안 남을 수 있으므로 백업 접근과 보존 정책 별도 관리 필요.

쿠키 삭제, 만료와 다른 기기의 기존 기록 복구는 미지원. 닉네임 중복 허용. 익명 참여자 복제, 자동 타이핑 및 개발자 도구 조작을 완전히 방지하는 대회급 안티치트는 범위 밖. 탭 이탈 정책은 정상 클라이언트에서 시행되며 악의적 클라이언트의 실제 가시성은 서버에서 증명 불가.

## 검사와 재현

`npm test`: 공유 판정, 한국어와 오류 수정, 30초 경계, 소유권, 동점 순위, 재시도, DB 장애 롤백, 삭제, 백업/복원, 빈도 제한.

`npm run test:e2e`: 별도 임시 DB와 테스트 시계 API 사용. 테스트 전용 실행 파일은 운영 이미지에 미포함. Chrome native 입력과 CDP IME, 서버 저장 실패 복구, 별도 쿠키의 순위 공유, 14개 테마의 효과 억제 및 6개 화면 크기 검사. 실제 OS 한글 IME와 실제 휴대폰 직접 조작을 대체하지 않음.

`scripts/load-challenge.ts`: 별도 DB에서 100명, 실제 3초 준비 + 30초 경기, 10분 반복. 매 회 100건 동시 제출 후 100건 재시도, 모든 개인 이력 검증. 가짜 시계 없음. 합성 API 부하로 브라우저 GPU 100개의 부하를 뜻하지 않음.
